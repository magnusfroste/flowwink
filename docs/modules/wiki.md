# Wiki

> Internal TEdit-style wiki / intranet for FlowWink.

## What it does

A lightweight, fast intranet for staff. Every authenticated user can read
and edit pages. Markdown body with TEdit-style auto-linking:

- `[[OtherPage]]` and bare `CamelCase` words become clickable links.
- Missing-page links render in red — clicking one navigates straight into
  edit mode for the new slug, so a page is created the moment you save.
- Double-click any page to switch from view → edit. `Esc` / Cancel to back out.

Use cases: HR onboarding checklists, support runbooks, internal SOPs,
"how do we handle X" notes that don't belong on the public website, blog,
or knowledge base.

## Tags, not a tree

The left column groups pages by **tag** — a label, not a folder. A page may
bear several tags and appears under each; groups are always open (no expander
to hit), newest first inside a group, so recurring notes ("Tisdagsmöte v39,
v38, v37") read as a series. Chips at the top narrow the column to one tag;
pages without a tag close the list under *Untagged*, visible rather than lost.

Two columns, one reader: `tags` is what the field says (UI pills, the agent's
`tags`/`add_tags`); `all_tags` is generated by the database — the field plus
every `#tag` written in the body (Bear-style). A `#tag` in the text follows
the text: it goes when the text changes and cannot be removed through the
field. Headings (`# Title`, with a space), colour codes (`#fff`) and URL
anchors are not tags. `wiki_tags` lists the tags in use — read it before
inventing a new spelling of an existing one.

Why not the tree: `parent_slug` and `manage_wiki_hierarchy` exist and stay for
agents, but no human surface ever set a parent, and a customer's 37 pages sat
at the root with the grouping done by hand in the titles ("Sälj - …",
"Produkt - …"). A title prefix is a label no code can read; a tag is.

## Skills exposed (MCP)

Handler: `module:wiki`. Both skills are MCP-exposed.

| Skill | Purpose |
|---|---|
| `manage_wiki_page` | `list` (optional `tag`) / `get` / `create` / `update` / `delete`; `tags` / `add_tags` |
| `search_wiki`      | term search over title + content_md, optional `tag` |
| `wiki_tags`        | tags in use with page counts, and how many pages have none |

The skills carry `Use when:` / `NOT for:` guidance so FlowPilot's general
scoring algorithm picks them only for internal-wiki intents (Law 1 & 2).

## Tables / RLS

`wiki_pages` (slug PK):

| Column | Notes |
|---|---|
| `slug` | PascalCase WikiWord, primary key |
| `title` | Human title |
| `content_md` | Markdown body |
| `created_by` / `updated_by` | `auth.users(id)` |
| `created_at` / `updated_at` | Stamped by trigger `wiki_pages_stamp` |

Access:
- **Read / insert / update**: any authenticated user (intranet model).
- **Delete**: admins only (`has_role(uid, 'admin')`).

## Cowork Chat integration

The `workspace-chat` edge function exposes `wiki` as a selectable knowledge
source. Support staff can toggle it in the Sources panel and ground
answers in the intranet alongside Documents, Contracts, KB, etc.

## Settings

None. The module is opt-in via `/admin/modules` (key `wiki`).

## Routes

- `/admin/wiki` → redirects to `/admin/wiki/HomePage`
- `/admin/wiki/:slug` → view/edit a page
